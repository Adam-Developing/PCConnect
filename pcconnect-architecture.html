PCConnect Modernisation Architecture

Moving a live remote-PC-control product from three parallel API generations and four clients to one secure, contract-driven system — without breaking the installed clients carrying today's traffic.

Assessed 2026-09-02 Branch Mobile-App @ 0b47ea2 Findings 39 · all traced Docs 22 files · 5,200 lines
Before anything else · Phase 0

Live production database credentials are sitting in the working tree

api/db_config.php holds the plaintext MySQL host, user and password for the production database. The file is untracked but not gitignored — one git add -A from permanent publication. The host is a public IP, which suggests the database is directly reachable from the internet. Alongside it, DB/pcconnect.sql holds roughly ten thousand rows of real user names, dates of birth, emails and password hashes.

Verified: the credential has not entered git history. It still needs rotating — it has lived unencrypted on a workstation. Nothing else in this architecture matters until that is contained.

The situation

Two complete systems, and only one of them has users

PCConnect lets someone shut down their PC from their phone. That makes remote code execution on a personal computer its core primitive — and today that primitive is guarded by a single permanent, unscoped, unrotatable bearer token, derived from a password the client hashes with unsalted SHA-256 before sending.

Backend

Three API generations

The live PHP endpoints — not present in this repository — serve 100% of traffic. A PHP front-controller in api/ cannot execute: four of its classes are zero-byte files. A working Node gateway in api_node/ serves nobody. The only written spec documents endpoints no implementation provides.

Clients

Two client generations

A VB.NET WinForms client on .NET Framework 4.7.2 and a Java Android app on deprecated AsyncTask carry all production traffic. A Go/Wails desktop client and a Flutter mobile app are prototypes that have never touched production. Neither generation can talk to the other's backend.

Data

A schema that causes bugs

No timezone anywhere, so reminders fire at UK time for users in Kolkata and Lima. utf8mb3, so reminder text cannot hold an emoji. And a single mutable row used as a command mailbox, so a shutdown queued at 09:00 executes when the laptop opens at 18:00.

The design

Five changes carry the architecture

Everything else in the document set is detail hanging off these.

C-1

Identity replaces bearer keys

Three credentials with different lifetimes and scopes: a password verified server-side with Argon2id, a 15-minute scoped access token, and a rotating refresh token with family-based reuse detection — plus a separate per-device secret in the OS keychain. A stolen phone token can issue commands but never receive them; a stolen device secret can execute on one PC but cannot read a reminder. No single credential does everything any more.

S1-03S1-04S1-05S1-10
C-2

Devices are paired, not asserted

The agent requests a short-lived pairing code, the user confirms it in the app, and the server issues a device id and secret. PCName stops being an identity claim and becomes what it always should have been: a label you can rename.

S1-08
C-3

Commands become an expiring, append-only lifecycle

The mutable mailbox row becomes an append-only table with a state machine, a client-generated id that makes retry idempotent, a mandatory TTL, and a per-command acknowledgement carrying the real outcome. Every transition writes an audit row — these are destructive actions on someone's computer, and "who asked for this, and did it happen" must be answerable.

S2-03S2-04S2-05
C-4

Encryption is decoupled from authentication

A per-user data key, wrapped by a key held outside the database, with AES-256-GCM replacing unauthenticated CBC. Rotating a credential no longer destroys data — which is what currently makes credential rotation impossible in practice.

S1-06S1-07
C-5

The contract is the schema

Route schemas validate requests and responses at runtime and generate the OpenAPI document at build time; every client's model layer is generated from it and a breaking change fails CI. This is what stops three parallel API generations from happening again — the failure was that the contract was prose.

Migration

Seven phases, gated rather than scheduled

A strangler-fig migration. Each phase advances when its exit criteria are met, not when an estimate elapses. The gates between them are the load-bearing part.

Every phase before P6 is reversible by reverting the application — the legacy schema and endpoints stay live and written throughout. P6 is the only one-way door, which is why it is last and gated on measured client traffic rather than a date.

Decision records

Eight decisions, each with its honest cost

Every ADR states what the choice buys, what it costs, and the condition that should reopen it.

0001 Node 22 + TypeScript on Fastify — port api_node, don't rewrite it

Cost: a build step, and Argon2id must be kept off the event loop. Revisit if CPU-bound work stops fitting.

0002 Argon2id, scoped JWT access tokens, rotating refresh tokens, separate device secrets

Cost: every client must ship first — while a client pre-hashes, no account can be upgraded.

0003 Socket.IO with a Valkey adapter; at-most-once delivery bounded by a TTL

Cost: a new runtime dependency, and a new user-visible failure — "your PC was offline". Correct, but needs explaining.

0004 AES-256-GCM envelope encryption — and a documented rejection of end-to-end

Cost: this protects against a stolen dump, not a compromised server. Said plainly rather than implied away.

0005 Stay on MySQL 8.4; adopt dbmate plain-SQL migrations

Cost: hand-written down-migrations, and the production drift gets baselined in rather than pretended away.

0006 Go + Wails, pinned to v2 stable; the v3 upgrade waits for GA

Cost: the transparent reminder window needs a v2 implementation, and the upgrade still has to happen later.

0007 Flutter for Android and iOS; retire the Java app

Cost: existing Android users install a new app rather than receiving an update. A real user-facing cost.

0008 Path versioning, a legacy shim, and a sunset gated on measurement

Cost: the shim carries one weak behaviour forward — confined, logged, rate-limited, and it dies with the shim.

Not everything needs replacing

What the existing code already gets right

  • The command allow-list in executor.go — enumerated argv, no shell, reject by default. It becomes the second of two enforcement points rather than the only one.
  • The fallback-polling policy in realtime/policy.go — exponential backoff, poll only when the socket is unhealthy. Small, tested, correct. It gains jitter and nothing else.
  • The Socket.IO room model — per-user and per-device rooms with presence broadcast. The right shape; the auth around it is what changes.
  • Windows Credential Manager integration — already the right home for a device secret.
  • The Flutter client's structure — feature-first, secure storage, biometrics. A good foundation to finish rather than restart.
